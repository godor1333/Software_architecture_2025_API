# forum-image-moderator

Мультимодальный сервис автоматической модерации изображений и текстов для форумов. Проект реализует распределённый пайплайн на базе микросервисов: анализ изображений с помощью модели CLIP (zero-shot), классификация текста, дедупликация контента по перцептуальному хешу (pHash), агрегация решений на основе мультимодальных сигналов и хранение результатов в PostgreSQL с полнотекстовой индексацией в Elasticsearch.

## Ключевые возможности

- Классификация изображений по категориям: violence, weapons, drugs, gambling, scam, spam, benign — на базе модели CLIP без дообучения.
- Анализ текстовой части поста (abuse, scam_text, clean) с помощью BERT-классификатора.
- Дедупликация загружаемых изображений: повторные публикации отклоняются на этапе обработки сервисом vision.
- Мультимодальная агрегация: финальный вердикт формируется на основе совместного анализа изображения и текста с применением цепочки правил и сменной политики модерации.
- Поддержка сменных политик (Strategy): standard, strict_family, spam_focus — переключение через переменные окружения без изменения кода.
- Асинхронная обработка через Kafka: разделение этапов приёма, анализа, агрегации и хранения; устойчивость к временным сбоям отдельных сервисов.
- Реализация архитектурных паттернов: Strategy, Chain of Responsibility, Observer, Facade, Adapter.

## Архитектура

Пайплайн построен как набор микросервисов, взаимодействующих через шину Kafka:

- api — REST-шлюз для приёма постов, загрузки медиафайлов в MinIO и предоставления интерфейса для получения вердиктов, статистики и поиска.
- vision — классификация изображений CLIP, расчёт pHash, проверка на дубликаты, публикация результатов в топик vision.verdicts.
- text — классификация текстовой части поста, публикация результатов в топик text.verdicts.
- fusion — объединение сигналов от vision и text по post_id, применение политики и цепочки правил, формирование итогового вердикта, публикация в moderation.events.
- indexer — запись результатов в PostgreSQL (с обеспечением идемпотентности) и индексация событий в Elasticsearch.

Инфраструктура: Kafka (шина сообщений), MinIO (объектное хранилище), PostgreSQL (хранилище данных), Elasticsearch (поисковый индекс), kafka-ui (панель мониторинга топиков).

## Запуск

1. Подготовить конфигурацию: скопировать шаблон в рабочий файл

        cp .env.example .env

2. Запустить все сервисы

        make up

3. Проверить статус контейнеров

        docker compose ps

   Все сервисы должны находиться в состоянии Up.

4. Провести демонстрационный прогон

        make demo

   Ожидаемый результат: RESULT: PASS и корректные вердикты по 8 тестовым изображениям (запрещённые категории — flag/reject, benign — approve, повторная отправка изображения — reject как спам).

Важно: перед каждым повторным запуском демо-теста перезапускайте сервис vision (docker compose restart vision) — таблица дедупликации хранится в памяти процесса и очищается при рестарте. Это осознанное ограничение демо-версии.

## Основные команды

- make up — поднять все сервисы в фоновом режиме с пересборкой образов.
- make down — остановить и удалить контейнеры (данные в томах сохраняются).
- make demo — выполнить демонстрационный тест на наборе тестовых изображений.
- docker compose logs -f <service> — просмотр логов выбранного сервиса.
- curl http://localhost:8000/health — проверка доступности API.

Пример отправки поста на модерацию:

    curl -X POST http://localhost:8000/api/v1/posts \
      -F "image=@data/demo/demo_00_violence.jpg" \
      -F "text=видео драки" \
      -F "user_id=tester"

Получение вердикта по идентификатору поста:

    curl http://localhost:8000/api/v1/posts/<post_id>

## Особенности и ограничения

- Модель CLIP загружается автоматически при первом запуске сервиса vision (требует доступа к сети, объём около 600 МБ).
- Кэш дедупликации реализован в оперативной памяти сервиса vision и сбрасывается при его перезапуске.
- Политика модерации задаётся через переменные окружения; в демо-режиме используется политика standard.
- Проект предназначен для локального развёртывания с помощью docker-compose.

## Структура проекта

- services/ — реализация микросервисов (api, vision, text, fusion, indexer).
- common/ — общие компоненты (работа с шиной Kafka, схемы данных, абстракции хранилища).
- scripts/ — скрипты для тестирования, генерации демо-данных и подготовки отчётов.
- data/demo/ — набор тестовых изображений для демонстрации и проверки.
- docs/diagrams/ — диаграммы архитектуры (C4) и схемы применяемых паттернов проектирования.
- artifacts/ — результаты прогонов и вспомогательные файлы для отчёта.
