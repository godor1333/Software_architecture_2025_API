## Как сдать проект

1. Сделайте **Fork** этого репозитория (или ветку, если вы добавлены в коллабораторы).
2. Положите файлы проекта **в свою папку проекта**: `projects/<Фамилия_Имя>/<N_название>/`. Там уже лежит `TASK.md` с заданием — его не трогайте.
3. Откройте **Pull Request** в ветку `main`.
4. После того как PR примут, галка в этом README и на сайте поставится **автоматически** (≈1–2 минуты).

## Что должно быть в отчёте

| Раздел | Обязательно раскрыть |
|---|---|
| Постановка задачи | Проблема, цель, пользователи, сценарии, входные/выходные данные. |
| Архитектура | C4 или аналогичная схема; сервисы; связи; синхронные/асинхронные взаимодействия; точки отказа. |
| Kafka / streaming | Topics, producers, consumers, consumer groups, формат сообщений, retries/DLQ, порядок обработки. |
| Хранилища | Выбор PostgreSQL/ClickHouse/Redis/Vector DB и обоснование; схема данных, индексы, retention. |
| API | Endpoints, схемы запросов/ответов, ошибки, авторизация при необходимости. |
| Паттерны | Минимум 3 паттерна; где применён, почему выбран, UML/схема и фрагмент реализации. |
| ML/CV/NLP | Датасет, preprocessing, baseline, модель, метрики, результаты, ограничения. |
| RL | Environment, state, action space, reward, алгоритм (PPO/DQN и т.п.), training curve, evaluation и baseline. |
| LLM/RAG | Модель, prompt/structured output, chunking, embeddings, vector search, retrieval quality, hallucination controls. |
| Видео/CV | Источник кадров, FPS/батчинг, preprocessing, inference, tracking/segmentation/detection и сохранение результатов. |
| Надёжность | Timeouts, retries, idempotency, circuit breaker, обработка падения consumer/service. |
| Docker | Dockerfiles, docker-compose, переменные окружения, инструкция запуска. |
| Тестирование | Unit + integration тесты, ключевые сценарии, результаты. |
| Демонстрация | Работающий pipeline, API, Kafka, ML/CV/RL/LLM часть и аналитический экран. |
| Выводы | Что сделано, измеримые результаты, ограничения, дальнейшее развитие. |
